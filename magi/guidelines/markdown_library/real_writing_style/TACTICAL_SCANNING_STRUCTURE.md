# Structured for Tactical Scanning and Execution

- Logical Headings and Sharp Dividers: Use clear section headers that enable Ctrl-F navigation. A good doc is navigable even when you're scanning it during a production incident.
- Bullet Lists That Deliver: Don't write bullet lists to fill space. Use them when you need to hammer in a checklist, priority order, constraint breakdown, or technical tradeoff. Use lists *to do work*.
- Code Blocks as Executable Examples: Include only what someone needs to get it working. Avoid toy examples unless you're explaining an API shape. Keep context tight and realistic — show what matters, skip what doesn't.
- Formatting That Does Not Waste Time: Headers are headers. Code is monospace. Emphasis is rare, deliberate, and functional. No markdown acrobatics, no table vomit unless it serves a purpose.
