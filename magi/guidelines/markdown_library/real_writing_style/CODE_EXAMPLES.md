# Code Examples

### Purpose and Placement
Code examples demonstrate correct usage, not syntax. Every example must:
1. Solve a realistic problem (not `foo`/`bar` placeholder scenarios)
2. Show complete, working code (not fragments that require imagination to complete)
3. Appear immediately after the prose explaining the concept
### Example Categories
- **Correct patterns**: Show the recommended approach with brief inline comments only for non-obvious decisions.
- **Prohibited patterns**: Show anti-patterns with clear labels (`-- PROHIBITED`, `// INCORRECT`, `# BAD`) and explain why they fail.
- **Comparative patterns**: When multiple valid approaches exist, show them side-by-side with trade-off analysis.
### Code Formatting
- Match the language conventions for the target technology
- Use realistic identifiers: `user_id`, `order_total`, `process_payment` — not `x`, `temp`, `doStuff`
- Include error handling when error handling is relevant to the point
- Omit boilerplate that distracts from the concept being demonstrated
