# Completeness Guidelines

Before considering a guideline document complete, verify:
- Core Principles section with Primary/Secondary/Tertiary rules
- Part-based organization following logical workflow
- Minimum 1,500 lines of substantive content
- 15+ realistic code examples that, typically, do **NOT** exceed 30 lines
- Decision frameworks for major choices
- Anti-pattern documentation for each major topic
- Tables summarizing comparisons and reference data
- Operational context (cost, scale, failure modes)
- Style Summary closing section
- No filler, hedge words, or repetitive content (again, referencing `Writing Style` from this document)
- All sections answer: what, when, how, why, and what-not-to-do
