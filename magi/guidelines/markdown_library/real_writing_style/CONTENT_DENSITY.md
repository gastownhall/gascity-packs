# Content Density and Length Requirements

### Minimum Scope
- Enterprise guideline documents must be comprehensive. Target metrics:
    - **Minimum length**: 1,500-2,500 lines depending on domain breadth
    - **Minimum character count**: 70,000-120,000 characters
    - **Section count**: 30-60 distinct H2/H3 sections
    - **Code examples**: 15-40 realistic, contextual examples that do **NOT** exceed 30 lines (with up to 50 lines **PERMITTED** for complex examples, though **NOT** preferred)
- These are minimums, not targets. The document is done when the domain is covered, not when a line count is reached. However, if a "complete" document falls significantly short of these minimums, the coverage is likely superficial.
### Information Density
Every paragraph must deliver information. Apply this test: if you removed the paragraph, would the reader lose anything? If not, delete it.
- No introductory filler: "In this section, we will discuss..." — cut it.
- No summary padding: "As we've seen above..." — unnecessary.
- No hedging: "You might want to consider..." — either recommend it or don't.
- No false precision: "In many cases..." — specify which cases or state the general rule.
- Generally, falling back to the `Writing Style` (in this document) when in doubt.
### Non-Repetitive Content
- Information appears once. If a concept is needed in multiple contexts:
    - Define it fully in its primary location
    - Reference it by section name elsewhere
    - Do not restate; readers can navigate
    - Again, falling back to the `Writing Style` (in this document) when in doubt.
- When similar patterns apply to multiple technologies or situations, use tables to show the variations rather than repeating prose with minor differences.
