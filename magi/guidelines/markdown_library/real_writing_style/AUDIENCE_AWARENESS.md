# Audience Awareness: Assume They Know Their Shit

- Write for Developers, Not Tourists: Don't define basic terms. Don't explain what an API is. Assume the reader knows what a REST call, enum, or UTF-8 string is. Focus on what *they don't know yet* about this system or tool.
- Preempt Real-World Concerns: Surface edge cases, common misuses, version incompatibilities, and runtime failure modes. If the reader might trip over it, call it out *before* they do.
- Enable Fast Mental Modeling: Favor descriptions that clarify how something fits into the bigger system — lifecycle, dependencies, failure states. Let the reader immediately understand where this thing plugs in and what happens if it breaks.
