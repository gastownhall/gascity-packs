# Value-Centric, Problem-Solving Orientation

- Start with "Why This Matters": Every section, bullet, and code block exists for a reason — state it. Don't just describe what a tool does; show how it reduces complexity, accelerates workflows, or eliminates an otherwise annoying bottleneck.
- Technical Utility > Feature Listing: Descriptions should convey usage context and intent. "This pipeline handles schema validation asynchronously to reduce request latency" is infinitely more valuable than "Supports async schema validation."
- Architectural Framing Is Mandatory: Call out benefits like reduced coupling, decoupled data contracts, improved observability, or config portability. These are the terms architects and senior engineers care about.
- Quantify Gains Where Possible: If a tool reduces boilerplate by 40%, say so. If it cuts CI runtime in half or prevents a known category of regression, mention it. No marketing gloss — just the raw win.
